# 局内编辑响应分析（2026-09-08）

## 测量范围与口径

本轮沿真实鼠标选择、单地块填色、工具栏撤销和重做追踪输入、命中、历史、颜色刷新、图层绘制、合成、侧栏更新。场景为 TNO，1600×1000，Berlin 投影点，实际命中 DE40D。沿用项目 input-evidence 探针，在 rAF 观察合成后的画布像素；这不是显示器物理呈现时间。稳定窗口包含额外 250ms 保持时间，不作为纯渲染耗时。

首次自然运行存在城市与本地化后台加载。第二次等待两者 loaded 后按动作单独采样 CPU；最终无 profiler A/B 单独保存。所有浏览器测量由主代理串行执行。

## 发现与处理优先级

| 环节 | 当前证据 | 决策 |
| --- | --- | --- |
| 输入排队 | 排除后台加载后约 0.2–0.6ms | 本组普通编辑瓶颈不在事件排队；不代表加载期间也如此 |
| 选择与命中 | 选择首次反馈约54ms；详情提升后重新命中有正确性意义 | 保留提升后重命中，不复用可能过期的命中结果 |
| 单地块颜色 | 首次可见约74ms，政治局部重绘约2ms | 不继续把政治细粒度绘制视为主要瓶颈 |
| 撤销/重做 | 首次可见约199/193ms；UI hook约40–50ms，flush约130ms | 收窄纯地块颜色历史的UI刷新；同步flush保留 |
| 附带图层 | contextBase约24–26ms，其中河流约11–12ms；labels约10–12ms | 颜色会影响城市/城镇自适应对比度，不能直接移除颜色失效 |
| 画布合成 | CPU样本中drawImage显著；改色后需要新合成 | 剩余重要方向；分组合成/局部合成需证明层序与失效范围后再改 |
| 城市资源复用 | 每colorRevision清空sprite缓存，现有key包含背景色等视觉输入 | 候选：完整视觉key加有界缓存；尚未实现或量化，需考虑连续尺寸与容量 |
| 河流几何 | outline和core各调用一次pathCanvas生成几何 | 候选：同次绘制复用几何；跨帧缓存需投影失效契约，尚未实现 |
| 连续笔刷 | 每新命中更新颜色/patch/request，结束统一history+flush | visited、抑制结束click、单笔历史语义必须保留；本轮未测持续笔刷p95 |
| 批量/所有权编辑 | owner索引查询后仍有全源扫描兜底 | 需先证明索引完整性；本轮未删除兜底，也未声称批量收益 |
| 后台资源处理 | CPU profile出现城市、本地化合并和GC | runtime ready不等于可选资源已完成；分开报告，不归入编辑自身成本 |

表中阶段有嵌套，不能相加为总耗时；CPU样本比例也不是端到端时间比例。单次profile数字用于定位，最终收益以无采样A/B为准。

## 本轮实现

`history_manager.js` 利用现有纯 feature color 快照识别器，仅对不含其他字段、且不影响 sovereignty 的历史收窄UI工作。保留颜色刷新、工具/色板/模式/活动对象及选中详情更新；其他历史继续完整UI刷新。原有同步渲染边界、颜色失效和所有权恢复不变。

移除历史流程中重复的 legend editor 更新是因为 idle render 本身调用 `renderLegend()` 和 `updateLegendUI()`。颜色恢复确实会改变 `state.colors`，不能用“没有修改图例配置”证明图例无需更新。

目标回归覆盖纯颜色的两种override、混合水域、所有权和现有局部颜色恢复。真实输入A/B结果另记于 `.runtime/reports/generated/business-efficiency-editing-results.md`。

## 验证边界

本轮只对上述单场景单点普通编辑量化。未完成跨剧本的持续笔刷、批量编辑、缩放中编辑、长期堆内存和p95测量。现有分析已经明确这些链路的候选与正确性约束，但不将静态分析写成性能收益。
